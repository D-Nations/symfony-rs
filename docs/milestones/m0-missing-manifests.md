# Manifests for every pinned package

November 25, 2026. Base: `7828feb`. Worktree: `../symfony-rs-wt-manifests2`;
branch: `m0/missing-manifests`. The three packages with a crate
(psr/log and the two contracts) are in a separate change
(`m0/crate-manifests`, [m0-crate-manifests.md](m0-crate-manifests.md)).

## Scope

The 50 remaining packages of `parity/packages.tsv` had no manifest. Each now
has `parity/<vendor>/<package>.tsv`, generated by `scripts/manifest.sh` on
`scripts/fetch-upstream.sh` checkouts at the pinned commits. No crate
changes.

Every row is `pending`: no Rust test in `crates/`, `examples/`, `spikes/`
or `fixtures/` has an `//! Upstream:` line naming a test file of these
packages (the spikes and the converter fixture name only source files), so
none is `ported`, and nothing was found inapplicable enough for `n/a`.
Four packages ship no PHPUnit tests (cache-contracts, http-client-contracts,
service-contracts and translation-contracts: their `Test/` base classes are
run by the components that extend them), so their manifests are the header
line alone, the convention for packages without tests. `parity/done.txt` is
unchanged.

## Generator changes (`oracle/manifest.php`)

Running the generator as it was on the 50 packages showed three faults of
its short-name `extends` matching inside `Tests/` only:

- **Wrong parents.** doctrine/dbal has two `AbstractDriverTestCase`
  classes (`tests/Driver/` and `tests/Functional/Driver/`); every
  `DriverTest` took the first one's tests (19 "ambiguous parent" warnings).
- **Parents outside `Tests/` dropped.** symfony/http-client's client tests
  extend http-client-contracts' `Test/HttpClientTestCase`, translation's
  `IdentityTranslatorTest` extends translation-contracts' `Test/TranslatorTest`,
  the Twig extras extend twig/twig's `src/Test/IntegrationTestCase`, and
  security-core / mailer use their own `Test/` base classes. Worse, for
  translation the short name matched the package's own `Tests/TranslatorTest`
  and listed its 38 methods under `IdentityTranslatorTest` instead.
- **Trait tests missed.** e.g. symfony/cache's `TagAwareTestTrait`,
  validator's comparison test traits.

And one host problem: on Docker Desktop (Windows) the bind mount is
case-insensitive, so `is_dir("$dir/Tests")` was true for a `tests/`
directory and doctrine, ux-* and twig/twig rows read `Tests/...`.

The generator now:

1. resolves a class's `extends` and trait `use`s to fully qualified names,
   from the file's `namespace` and `use` imports (aliases, group uses,
   `\`-qualified and `namespace\` names), as PHP does;
2. indexes classes and traits of the whole package (not only `Tests/`) and
   of the pinned checkouts of its composer.json `require` and
   `require-dev` packages, then their `require`s (their own `Tests/`
   skipped); only classes under the package's `Tests/` give rows;
3. lists the test methods of used traits, recursively, with the parents';
4. picks `Tests/` or `tests/` by exact name.

Nothing is loaded or executed; it is still PHP's tokenizer only.

**Existing manifests.** All 16 regenerated: 15 are byte-identical. Only
symfony/translation changes, all on `pending` rows of
`IdentityTranslatorTest`: 37 rows of the package's own `TranslatorTest` out,
11 of the contracts' `TranslatorTest` in (`testTrans` is in both), 345 to
319 tests. It is a separate commit so it can be reviewed on its own.

Not checked against PHPUnit's own `--list-tests` (most of these suites need
packages or extensions the oracle does not install, as for http-foundation
before); spot checks: dbal's `Functional/Driver/Mysqli/DriverTest` lists
the three tests of its own parent, http-client's `CurlHttpClientTest` 129
rows with HttpClientTestCase's.
